# 前端表单动效与购物车重设计

- 日期：2026-08-02
- 状态：已完成（真实设备待补验）
- 关联需求：F-06、F-08、F-09、F-10、F-11、N-03、N-06

## 目标

统一公开前台与后台表单的填写、焦点、校验、提交和反馈体验；重做商城桌面购物袋与移动端购物车 Sheet；修复预约页参观路线示意中文本未被空间框包含的问题。

## 影响范围

- `frontend/src/components/`：购物车内容组件、Bottom Sheet 焦点与滚动管理。
- `frontend/src/views/ShopView.vue`：商品加入状态、桌面购物袋和移动购物车复用同一交互结构。
- `frontend/src/views/AppointmentView.vue`：路线示意和表单输入语义。
- `frontend/src/assets/main.css`：表单状态、购物车布局、Sheet、响应式和减少动态规则。
- 项目状态与需求追踪文档。

不修改后端 API、数据库、认证权限、库存规则、订单金额或模拟支付状态机，不新增依赖。

## 实施步骤

1. 建立可复用购物车内容组件，使邮箱成为真实结算表单的一部分，并统一商品数量、删除、空状态与支付说明。
2. 重排桌面购物袋为固定标题、可滚动商品区和稳定结算区；移动端复用相同内容并保留可拖拽 Sheet。
3. 统一登录、个人资料、预约、商城、搜索和后台表单的焦点、校验、禁用、按压与提交反馈。
4. 重画预约路线 SVG，让入口广场、核心展厅、文创空间的文字分别位于对应空间框内。
5. 运行类型检查、单元测试、生产构建，并在桌面与手机视口验证商城、预约和表单关键流程。

## 验收标准

- 购物车邮箱为空或格式错误时，浏览器阻止结算；商品数量和删除操作有即时反馈且不会改变布局。
- 购物车商品较多时只滚动商品区，标题和结算操作保持可见；桌面和移动端使用同一数据与交互语义。
- 所有表单控件具有清晰的 hover、focus、invalid、disabled 状态，触控目标不小于 44px。
- Bottom Sheet 可通过拖拽、遮罩、关闭按钮和 Escape 关闭；打开后焦点进入面板，关闭后返回触发控件。
- 预约路线三段文字完整位于各自空间框内。
- `pnpm typecheck`、`pnpm test`、`pnpm build` 通过，桌面和手机端无关键横向溢出或遮挡。

## 风险

- 当前工作区已有大量未提交改动，本轮只追加与表单、购物车和预约示意相关的实现，不重置其他改动。
- 真实手机触摸与系统级辅助功能媒体偏好仍需最终设备复验；本轮先完成浏览器模拟与代码路径检查。
