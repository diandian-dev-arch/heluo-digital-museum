# 内容模块实施计划

- 日期：2026-08-01
- 状态：实施中
- 关联需求：F-01、F-02、F-03、F-04、N-01、N-02、N-03、N-06。
- 依据：[需求追踪表](../01-requirements-traceability.md)、[API 契约](../05-api-design.md)、[ADR-003](../decisions/ADR-003-content-soft-deletion.md)。

## 目标

完成“公开浏览内容 + 管理员维护内容”的第一个端到端业务闭环：游客可以按分类浏览、搜索和查看已发布文物/文章；管理员可以创建、编辑、发布、撤回、软删除并恢复文物和文章。第一批演示数据只引用仓库内已登记的自创图片。

## 影响范围

- `backend/`：内容公开接口的分页、查询参数、错误语义；受 `ADMIN` 角色保护的后台内容接口；开发演示数据初始化。
- `frontend/`：探索列表、详情、搜索结果、加载/空/失败状态和管理员内容管理页。
- `deploy/`：仅在需要新增安全环境变量时更新示例配置。
- `docs/`：本实施计划、需求追踪表和项目状态。

## 实施步骤

1. 规范公开内容接口：仅返回已发布、未软删除内容，支持分类、关键词和分页；公开详情对不存在、撤回或删除内容统一返回 `404`。
2. 实现后台分类、文物和文章管理接口：服务端校验 `ADMIN`，并落实 `DRAFT → PUBLISHED → WITHDRAWN`、软删除和恢复为 `WITHDRAWN` 的规则。
3. 创建受环境变量控制的唯一管理员初始化与第一批开发演示内容；不得把管理员密码写入仓库。
4. 实现前台“探索馆藏”、文物详情、文章详情和搜索交互；实现最小后台内容管理界面。
5. 执行后端测试、前端类型检查/单测/构建、Docker 浏览器验收；记录结果。

## 验收标准

- 游客能在前台看见已发布内容，分类筛选、关键词搜索、详情、无结果、加载和失败反馈均可用。
- 未发布、撤回和已软删除内容不出现在公开列表、搜索或详情中。
- 非管理员调用 `/api/v1/admin/**` 返回 `403`；管理员可完成文物和文章的创建、编辑、发布、撤回、删除、恢复。
- 被恢复的内容状态为 `WITHDRAWN`，必须再次发布后才公开可见。
- 不在数据库或仓库保存明文管理员密码；演示图片均引用项目内自创资产。

## 风险

- 当前初始数据为开发演示数据，后续正式馆藏资料需由项目组核对史实和文案。
- 后台编辑器第一版使用纯文本正文；富文本、图片上传和多媒体图库不在本阶段扩展。
- 需要在 Docker 的 `.env` 中提供管理员初始化和 JWT 配置；真实凭据不进入版本控制。
