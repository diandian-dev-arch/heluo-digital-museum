# API 契约实施计划

- 日期：2026-08-01
- 状态：已完成（文档设计），等待工程脚手架阶段实现
- 关联：F-01 至 F-13、N-01、N-02；`docs/05-api-design.md`。

## 目标

将已确认的数据模型和状态机转换成统一的 REST API 契约，避免前后端分别猜测参数、权限和错误行为。

## 已完成

1. 统一 API 前缀、认证、响应信封、分页、金额、时间和幂等键规则。
2. 设计认证、公开内容、后台内容、预约、商城、订单、模拟支付、用户和统计接口。
3. 指定公开/用户/管理员权限边界和常见 HTTP/业务错误码。
4. 约束库存锁定、重复支付、状态转换、软删除和邮件通知失败的处理边界。

## 工程阶段验收

- 每个实现接口在 OpenAPI 中与本文的路径、请求、响应、权限和错误码一致。
- 每个写接口均有服务端输入校验；所有资源归属和管理员权限均由后端校验。
- 支付、预约名额和状态变更通过事务/并发控制验证。
- API 修改需要同步更新本文、OpenAPI、相关测试和需求追踪表。
