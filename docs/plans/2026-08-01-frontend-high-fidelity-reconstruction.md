# 方案 B 高保真前端重建实施计划

- 日期：2026-08-01
- 状态：已完成（待项目组视觉确认）
- 关联需求：F-01、F-05、F-06、F-09、F-12、N-03、N-06
- 视觉基准：`assets/design-mockups/2026-08-01-frontend-redesign/curation-01-home-v2.png` 至 `curation-05-shop.png`

## 目标

以效果图原始桌面尺寸为 Golden Viewport，重新建立五个核心页面的布局、素材、比例与交互细节。保留真实 API、登录、预约、商城、模拟支付和 Three.js 逻辑，不使用整张效果图充当页面背景。

## 影响范围

- 全局页面骨架、导航、字体、设计令牌与响应式规则。
- 首页、馆藏、3D 展项详情、预约和商城五个核心页面。
- 新增透明青铜鼎、白色数字展厅和水墨馆舍等自创 Web 资源。
- Three.js 视角控制与展台展示，不修改后端接口或数据库结构。

## 实施步骤

1. 新增并登记自创视觉素材，统一为适合 Web 加载的 WebP/PNG。
2. 重写全局设计系统与五个页面的桌面构图，优先匹配效果图边界和标题换行。
3. 为 3D 展项增加旋转、缩放、复位和预设视角；为预约增加日期与时段联动。
4. 在效果图原始尺寸、1440×900、768×1024 和 390×844 下完成浏览器视觉回归。
5. 运行类型检查、测试、生产构建与 Docker 验证，更新状态和需求追踪。

## 验收标准

- [x] 五个页面在 Golden Viewport 下的布局、比例、色彩和标题换行与效果图高度一致。
- [x] 页面文字和控件均为真实 DOM，动态数据来自既有 API。
- [x] 搜索、分类、3D 控制、日期/时段联动、登录跳转、购物车和模拟支付逻辑可用。
- [x] 桌面与 390px 手机宽度无关键横向溢出。
- [x] `pnpm typecheck`、`pnpm test`、`pnpm build` 与 Docker 服务检查通过。

## 风险

- 效果图包含概念素材和固定数据，代码实现需要用真实接口状态替代，文字长度可能产生小幅视觉差异。
- 工作区已有其他未提交业务改动，本任务不得重置或覆盖无关文件。
- 新增图像和字体必须本地化并记录来源，禁止依赖运行时 CDN。

## 验证结果

- Golden Viewport：在 `1630×965` 首页及 `1672×941` 馆藏、3D、预约、商城完成浏览器截图核对。
- 响应式：完成 `1440×900`、`768×1024` 与 `390×844` 视觉检查；日期条使用组件内部横向滚动，页面本身无关键横向溢出。
- 交互：馆藏分类与关键词搜索、3D 放大/预设视角/点云/复位、预约日期与时段联动、游客加入购物车跳转登录均已浏览器验证；另创建隔离回归用户，完成购物车数量更新、创建订单与模拟支付，支付后购物车清空。
- 工程检查：`pnpm typecheck`、`pnpm test`、`pnpm build` 通过；Docker Compose 重建后 MySQL 健康、前后端容器运行。
- 商城标注回归：商品网格改为三列等宽卡片，商品图说明增加独立层级和半透明底，文字不再被丝巾/笔记本主体遮挡；1280px 浏览器实测三张卡片宽度约 282px、页面无横向溢出。
- 已知项：Vite 仍提示字体 CSS 与 Three.js 主包体积较大；不影响本轮功能验收，后续可通过字体子集和路由级拆包继续优化。
