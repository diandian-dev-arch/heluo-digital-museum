# 专题文章正文恢复计划

## 目标

恢复公开馆藏页三篇专题文章的完整正文，使既有 Docker/MySQL 数据库和全新初始化数据库都能获得一致内容，并保持现有文章路由、接口和前端阅读结构不变。

## 关联需求

- `F-01`：游客可浏览已发布文章。
- `F-03`：游客可查看包含正文、分类和封面的文章详情。

## 影响范围

- Flyway 文章数据修复迁移。
- 新数据库的演示内容初始化逻辑及测试。
- 项目状态和需求追踪记录。

不修改 API、表结构、权限、前端路由或视觉样式。

## 实施步骤

1. 为 `how-to-read-bronze`、`river-as-timeline`、`why-negative-space-matters` 编写分章节完整正文。
2. 新增 Flyway 迁移，更新既有数据库中的三篇文章。
3. 同步 `BootstrapDataInitializer`，保证全新数据库写入同一内容。
4. 扩展初始化测试，验证文章正文不是旧的三段短文。
5. 运行后端测试、前端类型检查/测试/构建，重建 Docker 并回归桌面和手机文章详情。

## 验收标准

- 三篇文章详情接口均返回至少 600 个字符、包含章节标题的正文。
- 三篇文章详情页能显示完整章节，无横向溢出和控制台错误。
- Flyway 在既有 MySQL 和测试 H2 数据库中通过。
- 后端测试、前端类型检查、单元测试和生产构建通过。

## 风险

- 迁移会覆盖这三个固定 slug 的现有正文；它们是项目内置策展文章，不影响管理员新增的其他内容。
- 长正文增加页面高度，需要在桌面与移动端复核滚动揭示和阅读进度。

## 验证结果

- 后端：`mvn test` 通过，11 项测试、Flyway V1–V20 均成功。
- 前端：`pnpm typecheck`、17 个测试文件 60 项测试、`pnpm build` 通过；构建仅保留既有 Rollup 注释和 Three.js 大 chunk 警告。
- Docker：前后端镜像重建成功，首页 HTTP `200`，`/api/v1/health` 返回 `OK/UP`，生产 MySQL 最新迁移为 `20 / expand article editorial content / success=1`。
- 数据：三篇文章正文长度为 `876 / 884 / 861`，分别渲染为 `13 / 14 / 14` 个内容块。
- 浏览器：`1433x746` 桌面与 `390x844` 手机文章详情正文滚动揭示正常，横向溢出为 `0`，控制台无 warning/error；另两篇手机路由同样完成标题、章节和宽度检查。
