## 1. 视频学习结论

视频页面可读到的章节是：

1. `00:19`：用模型工作台确定模型姿态和构图；
2. `00:41`：将构图截图和提示词交给 Image 2，先确认网页视觉效果；
3. `00:59`：将满意的效果图、原始模型和点云网页提示词交给 Codex，实现可预览网站。

因此，本方案采用“构图基准 → 视觉基准 → 代码实现 → 浏览器验收”的链路。视频没有证明某个固定的点云库或固定 shader 配方；点云动效仍需根据本项目模型、设备性能和无障碍要求实现。

## 2. 当前基线与发现

### 已有能力

- `ThreeExhibitViewer.vue` 已有 GLTFLoader、MeshSurfaceSampler、GPU `ShaderMaterial`、实体/点云切换、旋转/缩放/预设视角和资源释放。
- 当前点数分档为高画质 `120,000`、标准 `60,000`、移动 `24,000`，低帧率会关闭 Bloom 或降级为实体。
- v5.4 GLB 保留 Cleveland Museum of Art 1962.281 的器型与纹样，页面已有深墨黑展厅、古青铜材质、来源信息和实体/点云控件。

### 需要在实现阶段修正的缺口

- `introStartedAt` 只声明未启动，当前不会自动播放“粒子聚合 → 实体”的入场动画。
- 点云已生成 `aColor`，但 shader 使用固定深墨玉/铜金混色，采样材质颜色未真正参与显示。
- 当前切换主要是 `uOpacity` 与实体透明度交叉淡化，缺少有节奏的“解构、漂移、回收、归位”阶段。
- 导览条当前是静态 `1 / 6`，没有与点云阶段和视角预设形成状态联动。

## 3. 推荐产品方向

### 推荐：A「首屏稳定，点云解构由用户触发」

- 刷新后立即显示实体模型，避免白闪和动效抢夺内容。
- 用户点击“点云”或导览中的“点云解构”后，播放约 `2.4s` 的解构动效，完成后进入可旋转的点云待机状态。
- 移动端不自动播放，仅在用户点击后播放；`prefers-reduced-motion` 下改为 `300ms` 淡入，不做空间漂移。
- 适合当前项目的公开展厅、课堂演示和真实设备性能边界。

### 可选分支

| 选项 | 行为 | 适用场景 | 代价 |
|---|---|---|---|
| B 桌面自动聚合 | 首次模型加载完成后，桌面端自动播放一次 `1.8s` 聚合，移动端仍点击触发 | 展示大屏、作品集 | 首屏动效更强，但需要处理刷新与加载时序 |
| C 全沉浸入场 | 进入页面先显示点云，再聚合成实体；实体/点云按钮保持可切换 | 展览开场、视频录制 | 首屏信息延迟，低端设备和减少动态用户体验较差 |

未确认前按 A 设计，不改变当前默认实体首帧。

## 4. 动效状态机

```text
LOADING
  -> SOLID_READY
  -> POINTS_INTRO (用户触发)
  -> POINTS_IDLE
  -> SOLID_TRANSITION (切回实体)
  -> SOLID_READY

任意状态 -- WebGL/GLB/低帧率失败 --> SOLID_FALLBACK
任意状态 -- prefers-reduced-motion --> REDUCED_MOTION
```

| 状态 | 时长 | 画面 | UI 文案/状态 |
|---|---:|---|---|
| `SOLID_READY` | 常驻 | PBR 实体、底座环线低速呼吸、少量尘粒 | `实体 · PBR 实体展示` |
| `POINTS_INTRO` | 0–240ms | 金色轮廓扫描一圈，实体边缘亮度升高 | `正在解构` |
| `POINTS_INTRO` | 240–900ms | 从器物表面向外散开，足部、器腹、双耳保持不同相位 | `点云解构 1 / 3` |
| `POINTS_INTRO` | 900–1,650ms | 粒子沿低幅螺旋/河洛曲线漂移，实体透明度降至 0 | `点云解构 2 / 3` |
| `POINTS_INTRO` | 1,650–2,400ms | 粒子回到表面采样位置，形成稳定点云 | `点云解构 3 / 3` |
| `POINTS_IDLE` | 常驻 | 点云轻微呼吸、每 8–12 秒一次弱金色脉冲 | `点云 · 粒子解构中` |
| `SOLID_TRANSITION` | 650ms | 点云向表面收拢，实体同步淡入 | `恢复实体` |

## 5. 视觉规范

- 背景继续使用深墨黑，不增加新的大面积渐变或发光球体。
- 点云主色：深墨玉 `#0E5A4A`；辅助色：古铜金 `#C5964B`；高光占比不超过总点数的 `12%`。
- 绝大多数点保持哑光、低亮度；只有边缘、纹样转折和随机种子点使用弱金色高光。
- 点尺寸按深度衰减并限制在 `1–8px`；移动端限制在 `1–5px`，避免满屏噪点。
- 点云与实体重叠时不使用强 Bloom；仅高画质允许弱 Bloom，标准/移动关闭。
- 底座暖金环线与点云脉冲错开相位，避免页面出现同时闪烁。

## 6. 可落地的 Three.js 实现契约

### 6.1 点数据

保留面积加权采样，并为每个点增加以下属性：

- `position`：模型表面目标位置；
- `aOrigin`：解构起始位置；
- `aColor`：来自 GLB 材质的基础色，经深墨玉/铜金调色；
- `aSeed`：可复现的随机种子；
- `aRegion`：区域编号，建议按网格名优先、按模型高度分带回退；
- `aPhase`：区域相位偏移，用于足部、器腹、双耳错峰。

随机数必须使用固定 seed 的伪随机函数，而不是每次加载都重新 `Math.random()`，以便录屏、回归截图和问题复现稳定。

### 6.2 Shader uniforms

```ts
uTime: number
uProgress: number       // 0 -> 1，解构进度
uOpacity: number        // 点云整体透明度
uTransition: number     // solid <-> points 混合
uPulse: number          // 导览或弱脉冲触发
uPointSize: number
uPixelRatio: number
uReducedMotion: number  // 1 时禁用漂移和脉冲
```

顶点阶段建议：

```text
scatter = easeOutCubic(uProgress)
regionT = clamp(uProgress * 1.25 - aPhase, 0, 1)
outward = normalize(aOrigin - position) * (1 - regionT) * scatter
drift = lowAmplitudeNoise(aSeed, uTime) * (1 - regionT) * (1 - uReducedMotion)
finalPosition = mix(position, aOrigin, regionT) + outward + drift
```

片元阶段建议：

```text
edge = smoothstep(0.34, 0.5, length(gl_PointCoord - 0.5))
regionColor = mix(deepJade, sampledBronze, aColorWeight)
glint = 1.0 + 0.12 * sin(uTime * 1.4 + aSeed * 20.0) * uPulse
alpha = disc * uOpacity * (0.82 + 0.18 * glint)
```

不要把动画逻辑写入 DOM 定时器；统一由 Three.js `requestAnimationFrame` 驱动，并在组件卸载时取消帧循环和释放资源。

### 6.3 交互触发

- 点击“点云”时调用 `startPointCloudIntro()`，重复点击不重新采样、不重建 GLB。
- 点击“实体”时调用 `startSolidTransition()`；过渡期间按钮保持可用，新的目标状态覆盖旧过渡，保证可中断。
- 导览第 5 步“点云解构”触发同一控制器，不复制另一套动画。
- 视角切换期间保留当前点云状态；相机动画与粒子动画独立，不互相重置。
- 双击重置只重置相机，不强制切换实体/点云。

## 9. 验收标准

### 功能与视觉

- 首屏无白闪，实体模型可见；点击点云后 2.4 秒内完成解构并进入稳定点云。
- 重复点击、快速切换实体/点云、切换预设视角均不会重载 GLB、闪烁或卡死。
- 点云轮廓、三足、双耳和主要纹样仍可辨识；高光不超过少量点，背景不被染成绿色。
- 导览第 5 步、模式按钮、状态文案和实际渲染状态一致。

### 性能与兼容

- 1440×900 高/标准设备持续运行 30 秒，平均帧率目标不低于 45；低于阈值按现有降级策略处理。
- 390×844 不横向溢出，点云按钮可触达，移动端点数不超过 24,000。
- `prefers-reduced-motion` 下无明显漂移、旋转或强闪烁。
- 页面离开后无 requestAnimationFrame、ResizeObserver、Controls、纹理、材质和几何体泄漏。

### 工程验证

- `pnpm typecheck`、`pnpm test`、`pnpm build` 通过。
- 浏览器控制台无新增 error/warning；失败分支通过可控 mock 或源码检查验证，不破坏线上数据制造失败。
- 真实手机补验触摸、发热、帧率、减少动态、高对比度和 Sheet 焦点。
