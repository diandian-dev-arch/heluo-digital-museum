# 青铜鼎背面视角修复计划

## 目标

修复三足青铜鼎数字展项选择“背面”后仍停留在前侧斜视角的问题，并保证相机切换过程不穿过模型。

## 关联需求

- F-05：游客可进入 3D 展厅查看并操作已发布展项。
- N-03：桌面和移动端核心操作可用。
- N-06：3D 交互实现可测试、可维护。

## 已确认原因

1. “背面”预设坐标为模型后方，但 OrbitControls 水平角被限制为正面约 `+-45` 度；每帧 `controls.update()` 会把背面坐标立即夹回前半区。
2. “俯视”预设同样受到最小极角限制，无法到达定义的俯视坐标。
3. 现有相机使用笛卡尔直线插值；正面切到背面会穿过模型中心。

## 影响范围

- `frontend/src/components/ThreeExhibitViewer.vue`
- `frontend/src/lib/exhibitInteraction.ts`
- `frontend/src/lib/exhibitInteraction.spec.ts`
- `PROJECT_STATUS.md`
- `docs/01-requirements-traceability.md`

不修改模型、材质、点云状态机、展厅底座、API 或数据库。

## 实施步骤

1. 增加围绕观察目标的球面轨迹插值函数，并覆盖正面到背面的中点与终点测试。
2. 相机预设过渡改用球面轨迹，保持距离并绕过模型中心。
3. 将 OrbitControls 方位范围调整到完整一周，并放开预设俯视所需的最小极角；保留距离和向下观察限制。
4. 运行类型检查、单元测试和生产构建。
5. 在 `390x844` 与 `1440x900` 下实际点击正面、背面、俯视，检查模型可见、按钮状态、画布像素和控制台。
6. 更新项目状态和需求追踪记录。

## 验收标准

- 点击“背面”后按钮保持 `aria-pressed="true"`，画面显示鼎的真实后侧，不再被夹回前侧斜视角。
- 正面到背面过渡全程绕模型旋转，不穿过器身或出现空白帧。
- “俯视”能够到达定义的上方相机位置。
- 旋转、缩放、重置、实体/点云和移动滚动策略不回归。
- `pnpm typecheck`、`pnpm test`、`pnpm build` 通过。

## 风险与回退

- 完整水平旋转会允许访客手动查看器物背面，这是五视角功能的预期能力。
- 仍保留最大极角，避免相机翻到展台下方。
- 若球面过渡异常，可回退到无动画的预设切换，不恢复会穿模的直线插值。

## 验证结果

- 新增球面轨迹插值测试：正面到背面过渡中点保持原观察距离、绕到模型侧方，终点准确到达背面坐标。
- `pnpm typecheck`：通过。
- `pnpm test`：9 个测试文件、31 项测试通过。
- `pnpm build`：通过；仅保留既有 Three.js 大分包和第三方 PURE 注释提示。
- `390x844` 浏览器回归：过渡中间帧、背面终态与俯视终态均保持模型可见；背面和俯视按钮分别暴露 `aria-pressed="true"`。
- `1440x900` 浏览器回归：背面中央铸接线和后侧纹饰完整可见，页面横向溢出为 0。
- 画布像素检查：正式移动场景熵为 `4.80`，RGB 标准差分别约为 `38.69/30.22/23.67`，不是空白画布；修复前后场景平均绝对像素差为 `12.20`。
- Docker Compose 标准重建尝试失败：容器内 Corepack 访问 npm registry 超时，应用代码和本地生产构建未失败。
- 使用同一份已验证的 `frontend/dist` 更新前端容器，固化为本地 `deploy-frontend:latest`，随后以该镜像重新创建 `deploy-frontend-1`。
- 正式 `http://127.0.0.1:8088/exhibits/heluo-bronze-ding-3d` 在 `390x844` 与 `1440x900` 下复验通过；页面、展项 API 和 health 均返回 HTTP 200，MySQL 健康。
- 正式移动页继续通过点云切换、放大、缩小和重置回归；重置后“正面”恢复 `aria-pressed="true"`，无页面错误。
- 控制台无页面错误；Chromium/Three.js 仍输出既有浮点精度警告，不影响渲染。
