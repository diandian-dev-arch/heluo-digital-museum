## 三、工作阶段

按以下顺序执行，不要跳过真实模型检查，不能直接从文字猜造型：

### 阶段 A：来源和 Blender 只读检查

1. 检查下载文件和项目备份是否存在，并重新计算 SHA-256；不一致时停止导出并报告。
2. 阅读 `SOURCE.md`，保留来源、CC0 许可、下载日期、原始文件名、文件大小和哈希。
3. 在 Blender 中以只读源文件为依据建立工作副本，记录 Blender 版本、GLB 导入结果、场景节点数量、Mesh 数量、材质数量、纹理数量、顶点数、三角形数、包围盒和尺寸单位。
4. 检查模型是否使用 Draco、是否有外部 `.bin` 或纹理依赖、是否有多个 Mesh、节点变换、负缩放、重复对象、相机、灯光、空节点、动画和异常法线。
5. 先输出真实扫描模型的正面、侧面、背面、顶部和透视预览，确认器腹、双耳、三足和原始纹样没有被误读或裁切。
6. 如果模型在 Blender 中显示为空、材质丢失、坐标方向异常或网格损坏，先修复工作副本并记录原因，不得用占位几何体掩盖问题。

### 阶段 B：v5.3 工作模型清理与网页优化

目标文件名：

- Blender 工作文件：`assets/models/bronze-ding/source/heluo-bronze-ding-v5.3.blend`
- 网页 GLB：`assets/models/bronze-ding/export/heluo-bronze-ding-v5.3.glb`
- 预览目录：`assets/models/bronze-ding/preview/`
- 处理说明：`assets/models/bronze-ding/source/heluo-bronze-ding-v5.3-SOURCE.md`

如果这些 v5.3 文件已经存在，不要静默覆盖；先比较来源和版本，必要时使用明确的 revision 文件名并在报告中说明。

清理要求：

1. 只清理不会改变器形的场景内容；移除相机、灯光和无用空节点前先确认它们不是模型层级的一部分。
2. 保留真实扫描模型的器腹、双耳、三足、口沿、底部和原有纹样，不凭空增加河洛纹、兽面、浮雕或镂孔。
3. 保持原始朝向为首选；只有当前端正面展示明显不合理时，才在配置中记录整体旋转修正，不能直接破坏源网格。
4. 统一场景原点、缩放和包围盒，使模型能被当前 `ThreeExhibitViewer.vue` 自动居中和适配相机。
5. 修复重复顶点、孤立几何、反向法线、非流形边和明显破面，但不要为了“好看”抹除真实纹理或改变轮廓。
6. 采用减面、合并材质或纹理压缩时，优先保持双耳、三足、口沿、轮廓和细纹样；记录减面前后的面数、误差和视觉损失。
7. 保留 UV；如果源模型没有可用 UV，必须明确记录，并使用可复现的重新展开或顶点色方案，不能声称成功读取原始贴图。
8. 处理后的网页 GLB 必须是单文件或拥有明确可复制的本地依赖，不允许依赖用户电脑中未记录的绝对路径。
9. 参考文件、原始 GLB 和导出 GLB 使用不同文件名；不得把优化文件伪装成原始下载文件。

材质要求：

- 以深褐黑、灰铜和少量暖色边缘磨损为主，避免塑料感和大面积均匀发光。
- 暗青铜绿只能出现在凹槽、接缝和局部氧化点，不能把整个器物涂成绿色。
- 使用可被 Three.js `MeshStandardMaterial` 或等效 PBR 材质正确读取的 Base Color、Normal、Metallic-Roughness、AO 资源。
- 如果贴图是由源模型或几何派生而来，记录“源贴图”与“派生贴图”的区别、制作方式和文件哈希。
- 禁止把点云辅助色当作实体模型材质写回 GLB。

### 阶段 C：接入当前项目点云展厅

当前项目不是独立的 10 秒静态网页，而是已有 Vue 展项组件。优先在现有架构内接入：

- 现有组件：`frontend/src/components/ThreeExhibitViewer.vue`
- 点云质量配置：`frontend/src/lib/pointCloudQuality.ts`
- 当前高画质点数：`120000`
- 当前标准画质点数：`60000`
- 当前移动画质点数：`24000`
- 低性能时允许降级为实体模型，并显示可理解的状态提示。

不要把原提示词中的“所有桌面分辨率固定 180000 粒子”直接搬进当前项目；除非明确创建独立的高保真展示页，否则必须保持上述项目质量分级、性能降级和移动端可用性。

模型接入要求：

1. v5.3 通过验收前，当前网站继续加载 v5.2；先在候选页面、开发开关或独立验证路径中加载 v5.3。
2. 通过验收后，才允许将 `frontend/public/media/models/heluo-bronze-ding-v5.3.glb` 作为候选网页资源，并保留 v5.2 回退路径。
3. 使用本地 `GLTFLoader`、`MeshSurfaceSampler`、Three.js 和已有本地 loader 资源，不新增 CDN 运行时依赖。
4. 遍历 GLB 中全部 Mesh，更新世界矩阵并基于完整模型包围盒计算中心、尺度和相机目标，不能只读取第一个网格。
5. 点云必须从三角形表面进行面积加权采样，不能直接把原始顶点当作最终点云。
6. 按 Mesh 表面积分配采样数量，保持三足、双耳、口沿和轮廓等重要结构的可见性。
7. 每个点至少保存目标位置、起始散开位置、颜色和随机种子；动画主要通过 GPU uniform 和 vertex shader 完成，不能每帧用 JavaScript 更新所有粒子位置。
8. 不能用复制第一个点或大量重合点来“补齐”粒子数量；采样分配必须从算法上保证数量与质量。
9. 优先从实际 UV/基础色读取点颜色，依次回退到顶点色、材质基础色和项目主题色，并在诊断中报告实际使用了哪一种。
10. 模型加载失败、没有有效三角形、纹理失败或点云采样失败时，显示现有项目的封面/文字降级状态和重试入口，不允许黑屏。
11. 页面离开或模型切换时释放 Geometry、Material、Texture、RenderTarget 和动画资源。

当前交互必须保留：

- 实体模型 / 点云切换；
- 前、左、右、后、顶等已有预设视角；
- 桌面 OrbitControls 和移动端触摸操作；
- 加载状态、错误降级、无障碍标签和减少动态效果；
- 现有展厅布局、信息面板和返回路径。

不要默认加入营销导航、商品卡片、登录入口、浮动广告、大型圆角卡片或独立的普通 Hero 页面。

### 阶段 D：点云动画与视觉方向

当前网站优先采用“加载 → 点云聚合 → 稳定展示 → 实体/点云切换”的交互，不强制自动 10 秒循环，也不自动把页面改成原提示词的全屏演出页。

点云效果应满足：

- 聚合前粒子从模型附近的克制散开位置进入目标表面，不出现完整实体模型闪现；
- 聚合运动有轻微随机漂移，但不能像爆炸倒放；
- 稳定阶段轮廓、双耳、三足、口沿和主要纹样清晰可辨；
- 点使用圆形软边、透明叠加和克制高光，不变成霓虹雾或连续发光实体；
- 轻微呼吸和闪烁沿表面法线进行，幅度很小；
- 不以 Bloom、透明度或点尺寸掩盖拓扑/纹样缺失；
- 深色展厅中保留暗部结构点，亮部不能过曝成白块；
- `prefers-reduced-motion` 下取消大幅散开、旋转和浮动，但保留信息、实体/点云切换和必要的淡入淡出。

如果未来明确要求单独制作“10 秒点云展演页”，再另建独立页面和配置，并将其与当前展项组件区分；不要为了套用原提示词破坏现有详情页交互。

### 阶段 E：响应式与性能

1. 保持当前页面桌面和移动端可用，不以牺牲核心操作换取特效。
2. 至少验证 1440×900、1280×800、768×1024 和 390×844；如果是独立展演页，再额外验证 1920×1080 和 2560×1440。
3. resize 只更新相机投影矩阵、渲染器尺寸、后处理尺寸和少量 uniform，禁止重新加载 GLB、重新表面采样或重建整个 BufferGeometry。
4. 使用渲染器实际像素比并设置合理上限；不能重复乘原始 `devicePixelRatio` 导致移动端过载。
5. 点尺寸随模型真实屏幕投影和深度连续调整，不能只用设备名称或离散 CSS 断点制造明显的疏密跳变。
6. 保留现有低帧率降级策略；验证高画质点云在桌面、标准画质在普通设备、移动画质在触摸设备上的表现。
7. 不在动画循环中创建大量临时 Vector3、数组或对象；不在每帧触发 DOM 重排。
8. 对 12.9 MB 原始扫描 GLB 的读取、Blender 处理和网页版本大小分别报告；不能把原始文件直接复制进前端后宣称已完成网页优化。
