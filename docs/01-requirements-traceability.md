# 需求追踪表

- 文档版本：v0.1（需求基线草案）
- 最后更新：2026-08-01
- 依据：当前项目需求概述与已确认的第一版范围。
- 生效规则：本文件在原始需求文档逐条核对、用户确认后才成为开发基线；确认前不得把“设计中”以外的需求推进为“开发中”。

## 1. 如何使用本表

- **优先级**：`P0` 必须完成，`P1` 应完成，`P2` 有时间再做。
- **状态**：`待确认`、`已确认`、`设计中`、`开发中`、`待验收`、`已完成`、`暂缓`。
- 每项进入开发前，要在 `docs/plans/` 创建实施计划；完成后必须写入验证结果并更新本表状态。
- “验收标准”必须可观察、可重复验证，不能只写“页面正常”或“功能完善”。

## 2. 产品范围与边界

### 本次第一版范围

```text
公开内容展示和检索
+ 3D 展项展示
+ 用户注册、登录与个人中心
+ 在线预约
+ 文创商品、购物车、订单、模拟支付
+ 前台中英文切换
+ 后台内容、展项、预约、商品、订单、用户和统计管理
```

### 目标用户

第一版主目标用户为 **18～30 岁的年轻文化探索者**，重点覆盖大学生和刚工作的年轻人。他们会先通过在线内容和 3D 展项感受博物馆，再决定是否预约线下参观。普通游客和亲子家庭可使用基础功能，但不作为第一版交互设计的主导对象。
### 明确不在第一版范围内

- 真实微信/支付宝等资金收款；支付仅为模拟状态流转。
- 公开管理员注册、真实短信通知、真实第三方登录。
- 多人实时导览、复杂社交功能、完整元宇宙场景。
- 未经批准的云服务、付费接口或来源/授权不明确的第三方资源。

## 3. 角色与访问范围

| 角色 | 能力 |
|---|---|
| 游客 | 浏览公开内容、搜索、查看 3D 展项和商品；不能提交预约或下单。 |
| 用户 | 具备游客能力；可维护自己的预约、购物车、订单和个人资料。 |
| 管理员 | 具备后台访问权；可管理内容、展项、预约、商品、订单、用户和统计。 |

## 5. 自创数字资产追踪

> 数字资产不是“最后找几张图补上”，而是与页面和 3D 展厅并行推进的独立工作流。开发期可以使用明确标注的占位素材，但最终展示前必须替换为自主创作资产。

| ID | 优先级 | 资产需求 | 最低交付物 | 验收标准 | 状态 |
|---|---|---|---|---|---|
| A-01 | P0 | 博物馆前台与商城所需图片自主创作 | 图片清单、原始/可编辑源文件、导出 Web 文件、用途说明 | 已替换核心页面占位图；每项可追溯到自创源文件；文件大小适合 Web 加载。 | 开发中 |
| A-02 | P1 | 3D 展厅所需模型自主创作 | 模型源文件、GLB/GLTF 导出文件、封面图、资产说明 | 至少一个模型在目标设备可加载、可交互；源文件与导出文件均保留；无来源不明的第三方模型。 | 开发中 |

资产目录和命名规范将在完成页面与 3D 方案后写入独立实施计划；不得将未经确认授权的网络图片或模型直接提交到仓库。

## 6. 非功能需求追踪

| ID | 优先级 | 需求 | 验收标准 | 验证方式 | 状态 |
|---|---|---|---|---|---|
| N-01 | P0 | 认证与授权 | 管理员接口后端校验 `ADMIN`；普通用户数据按当前用户隔离；未登录 401、越权 403。 | 权限回归测试 | 已确认 |
| N-02 | P0 | 输入与数据安全 | 对表单/API 输入做服务端校验；不得泄露密码、令牌、堆栈和数据库细节。 | 接口测试；代码审查 | 已确认 |
| N-03 | P1 | 易用性与响应式 | 桌面和手机端无关键横向溢出；表单具有标签、错误提示和可理解的空/失败状态。 | 浏览器验收 | 已确认 |
| N-04 | P1 | 性能目标 | 原始需求确认后，明确测试环境、接口范围、并发量、P95 响应时间和允许失败率。 | 压测脚本与报告 | 已确认 |
| N-05 | P1 | 可部署与可恢复 | 提供 `.env.example`、启动文档、数据库迁移；部署后通过服务状态/健康检查验证。 | Compose 验收 | 已确认 |
