# 测试与验收计划

- 文档版本：v1.0
- 最后更新：2026-08-01
- 依据：需求追踪表、用户故事、数据模型、ER 图和 API 契约。

## 1. 测试目标

证明系统不仅“页面能打开”，还满足核心用户路径、角色权限、状态流转、库存一致性、软删除、邮件失败边界和可部署性要求。

## 2. 环境与测试数据

| 环境 | 用途 | 数据规则 |
|---|---|---|
| 本地开发 | 单功能开发与调试 | 使用独立本地数据库和 `.env`，不得使用真实密码/生产数据。 |
| 自动化测试 | 后端、前端、集成测试 | 每次测试独立建库或事务回滚，使用固定种子数据。 |
| 演示环境 | 浏览器验收与课程展示 | 使用可重复导入的演示数据，包含自创图片和至少一个自创 GLB 模型。 |

最小种子数据：一个 `ADMIN`、两个普通用户、三个分类、至少三件文物、三篇文章、一个 3D 展项、两个预约时段、三件商品。

## 3. 测试层级与工具

| 层级 | 计划工具 | 覆盖重点 | 通过标准 |
|---|---|---|---|
| 后端单元/服务测试 | JUnit 5、Spring Boot Test | 状态机、密码、库存、预约名额、幂等性 | 所有测试通过。 |
| 后端接口集成测试 | MockMvc、测试数据库 | DTO 校验、HTTP 状态、认证、资源归属 | 关键接口正向和负向路径通过。 |
| 前端单元测试 | Vitest | 表单校验、状态展示、API 状态处理 | 核心组件测试通过。 |
| 浏览器 E2E/手工验收 | Playwright 或等价工具 | 登录、预约、下单、后台 CRUD、3D 加载 | 每条关键用户路径可复现通过。 |
| 构建与配置检查 | pnpm、Maven、Docker Compose | 类型、构建、测试、容器配置 | 全部命令通过。 |
| 性能与安全检查 | 压测脚本、代码/接口审查 | 公开读接口、输入校验、权限隔离 | 达到确认后的 N-04 指标，无严重权限漏洞。 |

## 4. 需求—测试追踪矩阵

| 需求 | 后端测试 | 前端/浏览器验收 | 重点负向场景 |
|---|---|---|---|

## 5. 必测用例

### 5.1 身份与权限

```text
注册普通用户 → 登录 → 读取个人资料 → 退出
禁用用户 → 旧令牌再次访问受保护资源 → 拒绝访问
普通用户调用 /admin/* → 403
普通用户请求另一用户预约/订单 → 403 或 404，不能泄露数据
忘记密码：绑定邮箱 → 请求重置 → 一次性令牌更新密码 → 旧认证失效
```

### 5.2 内容与 3D

```text
管理员创建草稿 → 发布 → 游客搜索并查看详情 → 撤回 → 公开详情 404
管理员软删除 → 前台列表/搜索消失 → 后台恢复为 WITHDRAWN → 再发布
打开已发布自创 GLB → 可旋转缩放 → 模拟加载失败有提示 → 离开页面无控制台资源错误
```

### 5.3 预约

```text
用户提交 30 人未满时段预约 → PENDING → 管理员 CONFIRMED → 邮件投递尝试
用户开始前 2 小时以上取消 → CANCELLED → reserved_people 正确释放
用户开始前不足 2 小时取消 → 拒绝
同一用户同一时段重复创建有效预约 → 409
并发提交使总人数超过 capacity → 至多一个成功，不超额
```

### 5.4 商城与模拟支付

```text
加入购物车 → 创建订单 → locked_stock 增加 → 30 分钟超时 → 订单取消并释放库存
创建订单后商品价格变化 → 结算使用当前价格并显示最终金额
使用相同 Idempotency-Key 两次模拟支付 → 返回同一成功结果，库存只扣一次
商品下架/软删除 → 历史订单快照仍显示；新订单不能购买
管理员将 PAID 订单标为 COMPLETED → 订单完成
```

## 6. 浏览器验收清单

每个核心路径至少在桌面端与 390px 宽移动端检查一次：

- [ ] 首页主题入口、内容列表、搜索、详情、3D 展厅可用。
- [ ] 登录、找回密码和个人中心提示准确。
- [ ] 预约表单要求联系人姓名、手机号、邮箱；状态和邮件提示准确。
- [ ] 商品、购物车、最终金额、模拟支付、订单状态可用。
- [ ] 普通用户看不到后台入口；直接访问后台被拒绝。
- [ ] 加载、空结果、网络失败、权限失败均有可理解提示。
- [ ] 手机端无关键横向滚动，按钮可触控，表单可填写。

## 7. 工程质量门禁

工程建立后，每次功能分支至少运行：

```powershell
# 前端
corepack pnpm typecheck
corepack pnpm test
corepack pnpm build

# 后端
mvn test

# 容器配置
cd deploy
docker compose config --quiet
```

合并或演示前追加：浏览器关键路径、OpenAPI 契约核对、数据库迁移从空库成功执行、`docker compose ps` 与健康检查。

## 8. 性能与安全验收边界

- N-04 的具体并发量、P95 响应时间和允许失败率必须以已确认的课程指标写入压测脚本与报告；在指标未落到文档前，不宣称“高并发达标”。
- 公开读接口优先压测内容列表、搜索、详情和商品列表；写接口单独验证预约名额、库存和支付幂等。
- 安全回归至少覆盖未认证、越权、IDOR、参数篡改、软删除绕过、重复支付、敏感数据泄露。
